# God's Eye View — 100 Ideas

> Working brainstorm doc for Ali's fork. Sections fill in over time; the goal is 100 concrete, valuable additions.
> Repo baseline: v0.1.1, ~92k lines vanilla JS, Cesium globe, 16 data layers, OpenAI Realtime voice, all `/api/*` routes living inside `vite.config.js`.

## Part 1 — First 20 (2026-09-09)

### ⚡ Faster (performance)

1. **Satellite SGP4 propagation in a Web Worker.** `src/data/satellites.js:63` re-propagates every satellite (Starlink ≈ 7,000) every second on the main thread. `SharedArrayBuffer` + `Float64Array` (lat/lon/alt), worker computes, main thread reads. `worldOverlayAllocation.worker.mjs` exists but is never wired with `new Worker`. Biggest quick win.
2. **Flights/AIS on `PointPrimitiveCollection` + `BillboardCollection` instead of Entities.** Entities choke above ~5k objects (AIS 12,000 vessels → 22 FPS). One draw call per collection. Same for FIRMS (100k detections).
3. **Detection overlay on OffscreenCanvas + Worker.** `detection.js`/`detectionDraw.js` drop the app to 34 FPS at 100% density. Keep projection on main thread, move drawing to a worker via `transferControlToOffscreen()`.
4. **Persistent server cache (SQLite/LMDB) instead of in-memory Maps.** Nearly every cache in `vite.config.js` is `new Map()` — cold on restart. Unified TTL cache for OpenSky/adsbdb/routes/terrain heights. CCTV cold activation is 19.6 s.
5. **Traffic tile prefetch ring + viewport prioritization.** Listed in `KNOWN-ISSUES.md`, never built: load 8 neighbor tiles after a city jump, visible roads first, adaptive dot cap by frame time (`trafficQueue.js`).
6. **Mobile / low-power profile.** `renderGovernor` gets a `profile` mode: `msaaSamples 4→0`, `resolutionScale 0.75`, detection/trails off, doubled poll intervals. Auto-detect via `hardwareConcurrency` / `deviceMemory`.

### 🏗️ Better (architecture & quality)

7. **Split `vite.config.js` (7k lines) into a real server (`server/`, Hono or Fastify).** Each `/api/*` route → `server/routes/*.js`. Enables `vite build` + `node server` production deploy, Docker, and always-on hosting on the Mac Studio.
8. **Break `ui.js` (10,310 lines) into panels + event bus.** `EventTarget`-based bus (`gev:layer-changed`, `gev:track-changed`) so panels stop cross-referencing each other; refactor incrementally.
9. **TypeScript via JSDoc `// @ts-check`, no rewrite.** JSDoc is already excellent; `tsconfig.json` + `checkJs: true` gives type checking for free. 168 test files untouched.
10. **Provider abstraction for LLM calls.** `hud-summary` and `analyst_query` don't need Realtime — route them through LiteLLM → Ollama/MLX on the Mac Studio. Keep OpenAI Realtime for voice (decided 2026-09-09: OpenAI stays for sound).

### 🌍 More (new data layers)

11. **Public transit layer (GTFS-Realtime).** DELFI (Germany-wide), VRN/RMV (Wiesbaden/Frankfurt) open feeds. Trains, buses, S-Bahn live — same render path as `flights.js` + `motionModel.js` dead reckoning.
12. **Weather radar + satellite imagery overlay (RainViewer).** Free tiles, open issue + PoC PR exist. `ImageryLayer` with time slider (last 2 h + forecast). Pairs with `cockpitCloudEffects`.
13. **Cellular/radio infrastructure: OpenCelliD towers + WiGLE.** ~40M towers, free. Hex bins at globe zoom, individual towers when close (LOD pattern from `cctvLod.js`).
14. **German/EU public-data pack.** `config/cctv_sources.germany.json` (Autobahn GmbH webcam API), DWD severe-weather polygons, Pegelonline flood gauges, DFS NOTAMs. Strong ThePuffer showcase.
15. **Time-travel / replay mode.** Currently `POSITION_HISTORY_LIMIT = 5`. IndexedDB ring buffer (24 h, ~50 MB) + timeline scrubber in `scene-panel`. Generalize the existing rocket-launch replay.

### 🧠 Intelligence

16. **Alerting / geofencing engine.** Rules like "military flight < 3,000 ft within 50 km of Wiesbaden" or "vessel `navStatus: aground`". `analystEngine.js` already filters; add persistent rule store + browser push / ntfy.
17. **Anomaly detection for flights/ships.** Squawk 7700/7600/7500, loitering (circles), AIS gaps (ship goes dark), TLE epoch jumps (satellite maneuvers). Pure client-side logic.
18. **Multi-entity watchlist with split screen.** Today exactly one `track_entity`. Watchlist (callsign / MMSI / NORAD) with 2–4 mini viewports or PiP canvas.
19. **Collaborative mode (shared session via WebSocket).** `sharelink.js` already serializes state; add a room where multiple browsers see camera, annotations, tracking in sync. Mac Studio hosts, team watches over Tailscale.
20. **Plugin / layer SDK with manifest.** `layers/*/manifest.json` (id, poll interval, credits, key requirement, voice enum) + dynamic `import()`. `GEV_REALTIME_TOOLS` becomes generated instead of sha256-pinned.

### Recommended order
- Feel "faster": 1 → 2 → 7
- ThePuffer showcase: 10 + 14 + 16
- 7 is the foundation for Docker, Mac Studio hosting, and the macOS app.

### 🖥️ Platform & hosting on the Mac Studio (21–30)

21. **`gev-server` as a launchd service on the Studio.** After #7, a `com.thepuffer.gev.plist` keeps the API + static build alive across reboots, logs to `~/Library/Logs/gev/`, restarts on crash. One `make install` target.
22. **Tailscale-only exposure with Tailscale Serve/Funnel + per-user identity.** `tailscale serve` terminates TLS and injects `Tailscale-User-Login` headers → the server knows who is connected without building auth. Team members get roles (operator / viewer) from a tiny `team.json`.
23. **Shared upstream key pool + per-user quotas.** One OpenSky/AISStream/TomTom/Google key on the Studio, spent fairly across the team: token-bucket per Tailscale identity, live "budget" HUD chip so nobody burns the TomTom daily tile budget alone.
24. **Central time-series store (TimescaleDB or DuckDB + Parquet).** The Studio has 8 TB — record every poll (flights, AIS, sats, fires, quakes) to disk. ~2–4 GB/day raw, far less with Parquet. This unlocks #15 replay, #17 anomaly baselines, and every "history" feature below. Retention policy configurable.
25. **Server-side fan-out: one upstream poll, N clients.** Today every open browser polls OpenSky itself. With the server owning the poll and pushing deltas over WebSocket/SSE, 10 team viewers cost the same upstream as 1, and browsers stop doing JSON parsing of 8k aircraft each.
26. **Precomputed "world snapshot" on server start.** Warm caches for all layers at boot (CelesTrak, Launch Library, Overpass for the 20 most-used cities, terrain heights) so the first client after a restart gets 0-second cold activation instead of 19 s for CCTV.
27. **Local LLM analyst on the Studio (MLX / Ollama via LiteLLM).** `hud-summary`, `analyst_query`, regional briefs, dossier generation (#57) all go to a local Qwen3/Llama model. Realtime voice stays OpenAI; the *thinking* happens at home. Zero token cost for the heavy stuff.
28. **Local STT/TTS fallback (Whisper + Kokoro) when OpenAI is down or over budget.** Same voice-tool contract, degraded but working. A "voice budget" toggle in Provider Settings picks the tier.
29. **Multi-GPU-aware render nodes (later).** For recording cinematic scene tours (`scenes/director.js`) headless on the Studio via Puppeteer/Chromium at 4K, queued as jobs — "render this tour and drop the MP4 into Obsidian".
30. **Observability: OpenTelemetry traces + a Grafana dashboard for the server.** Upstream latency, cache hit rates, per-layer error rates, cost per hour per provider. Also feeds the Graphify/Obsidian project map.

### 📍 Places & commerce layer — "every place on Google Maps" (37–52)

37. **Places as a first-class layer (`places`).** Google Places API (New) *and* OpenStreetMap/Overpass POIs as fallback, cached in SQLite on the Studio (Google ToS allows 30-day caching of place IDs; store the rest yourself from OSM + your own enrichment). LOD: category clusters at globe zoom, individual pins below 5 km, building-snapped labels below 500 m.
38. **Click any building → "what's inside" card.** Name, category, opening hours (open now?), rating, price level, photos, website, phone, social links, and the OSM building footprint highlighted. Voice: "what is this building?".
39. **Website intelligence per place.** Server-side fetch of the place's website → tech stack (WordPress? Shopify? Wix? Nothing?), SSL state, mobile-readiness, has online booking?, has menu online?, Impressum present (DSGVO angle), last-updated signal. This *is* ThePuffer's sales qualification, automated.
40. **Social & review pulse.** Google review velocity (reviews/month), average rating trend, Instagram handle presence, TikTok mentions, Tripadvisor. Flag "declining" places (rating drop + review drought) — those are the ones that buy IT/AI help.
41. **Lead pipeline overlay (CRM on the globe).** Every place can be tagged: `cold / contacted / visited / demo / pilot / customer`. Colors on the globe, filters in the panel, notes and next-action date. Syncs to your CRM of choice (Notion, Asana, or a simple SQLite table). Merges with the `venue-visit-playbook` skill.
42. **Route-planned visit days.** "Plan my Thursday: 8 bars in Wiesbaden Innenstadt I haven't visited, walking order, 20 min each" → uses the existing `/api/route` + `fly_route` cinematics to preview the walk, exports to Apple Maps/Calendar.
43. **Competitor/peer map for a venue.** Select a bar → show all bars within 800 m, their ratings, opening hours overlap, price level. Basis for a TheBarApp pitch: "you're the only one of 12 without online reservations".
44. **Live-experience layer (Bloghead).** Events tonight from Bloghead's own DB + Eventbrite/Songkick/Bandsintown/Resident Advisor, plotted at the venue. Artists on tour drawn as arcs between venues, like flights. "Who's playing within 30 km tonight?".
45. **Crowd & busyness estimation.** Google Popular Times (where available), plus derived signals: bikeshare dock churn (`bikeshare.js` already loads GBFS), traffic density, transit arrivals (#11). A "pulse" glow on places that are busy *now*.
46. **Menu & price intelligence.** For gastro places: scrape/OCR the menu (or pull from TheBarApp when they're a customer) → average beer/cocktail price heatmap by district. Dehoga-relevant market data.
47. **Workforce signals (Dehoga marketplace).** Job postings per place (Indeed/StepStone/Google Jobs API), "Personal gesucht" signs detected in Street View / camera frames via a vision model. Places hiring = Dehoga leads.
48. **Commerce: book/subscribe/pay from the globe.** For places that are TheBarApp/ThePuffer customers: reserve a table, buy a ticket (Bloghead), subscribe to a venue's newsletter — Stripe checkout embedded in the place card. The globe becomes a storefront for your own ecosystem.
49. **Place ownership graph.** Company register data (Handelsregister via OffeneRegister / North Data), owner → other venues → linked companies. Click a bar, see the GmbH behind it and its 3 other locations. OSINT + sales in one.
50. **Real estate & rent overlay.** ImmoScout/Immowelt listings for commercial space, ground-floor vacancies (OSM `disused:shop`), Bodenrichtwerte (BORIS, official land values). "Where would I open the next venue?"
51. **Street-level continuity.** From a place card jump to Google Street View / Mapillary (free) at the entrance, with the existing `tools/streetview-*.mjs` heading math. Then to the nearest CCTV (already in the codebase: tracked → nearest camera handoff).
52. **User-contributed places & corrections.** Team members add/correct places (hours, closed, new owner) → stored locally, optionally pushed to OSM. Your own ground truth beats Google's for Wiesbaden.

### 🕵️ Serious OSINT toolkit (53–64)
